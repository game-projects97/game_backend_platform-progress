02 / ORIGINAL BLUEPRINT

원기획의 10개 항목과 연결

11월 3일 재구성안의 목차를 유지하고,
11월 7일 이후 구현 결과로 업데이트했습니다.

01제품 경계+

운영 콘솔·게임 API·서버 업무 규칙은 로컬 제품으로 연결했다. 실시간·비동기 실행과 외부 공급자까지 완성된 상태는 아니다.

02기능을 내부 모듈로 대응+

최신 PLATFORM 설계의 P1–P9로 추적한다. 아래 단계별 표가 원기획의 모듈을 현재 코드·검증·잔여 작업에 연결한다.

03데이터 모델 후보+

프로젝트/환경, 관리자/역할, 유저/세션, 진행·데이터, 지갑/원장, 콘텐츠·소셜 등의 SQLite 스키마를 DB22까지 구현했다. 캐릭터·외부 거래·실시간·정리 정책은 남아 있다.

04신뢰 경계와 경제 상태+

서버 인증·환경 권한, expected_version과 request_id, 상태·명령·감사의 원자 처리를 구현했다. 게임별 점수 신뢰와 외부 검증→지급→환불 경로는 미완료다.

05자체 API에서 정할 계약+

현재 Rust API와 기능별 계약 문서는 있다. 기계 판독 OpenAPI, SDK 공개 타입, 소비 게임의 실제 필드 매핑까지 완료된 것은 아니다.

06운영 콘솔의 책임+

React 관리 화면은 주요 기능에 연결했다. 기능 우선 방침에 따라 문의·탈퇴 UI와 전반 리팩터링은 남았다. 실제 UI 전역/반응형 검증도 별도다.

07성능과 운영 품질+

기능 검사와 로컬 측정은 축적했다. 일부 p95 증가 원인과 성능 동등성은 미확인이다. 운영 SLO·부하는 실제 배포 이후로 연기한 상태다.

08구현 순서 후보+

관리 기반에서 계정·데이터·경제·경쟁·소셜로 확장했다. 다음 수직 흐름은 고객 문의이며, 이후 탈퇴 정리·지연 원인·복구/연동·UI 순서로 이어간다.

09재구성 검증 기준+

권한·경합·원자성·재전달·자료 보존·일부 강제 종료/재시작의 근거가 있다. 실제 복원·게임·외부·실시간·운영 용량의 합격과 구분한다.

10콘솔과 REA 후속 조사에서 확정할 항목+

공식 기능, 제한적 콘솔 실험과 관측 요청을 조사했다. 원본 문서/관측 수치는 자체 제품의 실행 검사 수가 아니며, 불명확한 계약은 필요한 경우에만 추가 조사한다.

PRD ALIGNMENT / ARCHITECTURE

초기 PRD v0.2와 현재 구현의 차이

초기 기능 목표와 최신 구현 선택을 구분합니다.
구조가 달라진 항목을 완료로 간주하지 않았습니다.

9월 13일 초기 PRD 대화에는 MSA, 별도 API Gateway, gRPC, 기존 Go 매칭 서버 통합이 포함되어 있습니다. 11월의 최신 구현 기준은 Rust 서버와 React 콘솔이며, 현재 로컬 실행은 Axum·SQLite 단일 프로세스입니다. 초기 구조 요구가 모두 취소되었다고 확인된 것은 아닙니다.

초기 PRD 방향현재 확인한 구현판정
MSA 서비스 분리기능 모듈을 나눈 Rust 서버와 React 콘솔독립 서비스 배포·장애 격리 미검증
별도 Gateway · gRPC · protoAxum의 HTTP /api/v1 계약별도 게이트웨이·gRPC 통합 구현 미확인
기존 Go Match Service최신 P8은 Rust 매칭·방 단계로 계획기존 Go 서버 연동 미확인, 역할·방향 재정합 필요
서비스별 DB ownership프로젝트·환경을 분리한 SQLite 파일 DB서비스별 저장소 분리 완료 아님
Event Bus · Outbox · Saga현재 도메인의 단일 DB 트랜잭션·멱등성분산 이벤트·거래 보장을 대신하지 않음
Redis · OpenTelemetry · Kubernetes로컬 캐시·감사·측정 기록해당 운영 구성의 실제 통합·배포 미검증

대화에 제시된 PRD 요약을 확인했습니다. 당시 첨부 DOCX 원문 자체는 이번에 열람하지 못했으므로 문서의 모든 요구사항 ID·수락 기준을 대조했다고 주장하지 않습니다. 장기 구조를 이어갈 때 최신 Rust 지정과 초기 MSA 요구의 적용 범위를 먼저 정합해야 합니다.
